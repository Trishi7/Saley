## 3. Design

### Tables (`0018_pack_auth_bot.py`)
- `web_session` (id_hash, user_id, provider, created_at, expires_at, revoked_at). The cookie holds a random token; the DB keeps only its hash.
- `scorecard_snapshot` (day, industry, people, contacted, connect_pct, reply_pct, meetings, deals; key (day, industry)), written by `metrics_snapshot` at 23:50. `metric_snapshot` has no industry scope.
- `weekly_pack` (week_start unique, built_at, body jsonb, post_id). One pack per week; a second run does nothing.
- `bot_post` queue (kind, shape, channel, for_user, body, rank, due_at, not_before, state queued|ready|sent|deferred|dropped, sent_at, msg_id, item_type, item_id, is_meeting, is_reconnect).
- `bot_exchange` (user_id, surface discord|dashboard, text, intent, refs jsonb, answer, window_from, window_to, left_out, created_at): the learn log (docs/03 §6.2).
- `decision.surface` allows `discord` if missing.
- Functions (SECURITY DEFINER, H4 downgrade pattern): `saley_session_start`, `saley_session_end`, `saley_ask_log`. Views for saley_ro: `v_weekly_pack`, `v_scorecard_delta`, `v_bot_queue_health`. Update `deploy/sql/roles.sql` and the grant tests.

### Sign-in (`web/auth.py`, D114–D116)
- `AUTH_PROVIDER=auto`: `google` when the client id, the secret and `WEB_ALLOWED_EMAILS` are set; else `mock`.
- `mock` works only with SALEY_ENV=dev and a loopback client. It signs in as `DEV_USER_EMAIL` (maps to `DEV_USER_SHORT`). A local form may send `email=` for allowlist tests. Anywhere else: 404.
- `google`: OAuth code flow with `state` + PKCE. The browser goes to accounts.google.com; the server talks only to `oauth2.googleapis.com/token` through egress (already allowed). The id_token comes from that TLS response (OIDC 3.1.3.7); check iss, aud, exp, `email_verified`. The email must be on `WEB_ALLOWED_EMAILS` (`short=email,...`, D35: never guessed).
- Every /api route needs a session in every mode. The loopback dev bypass in `current_user` goes away.
- `X-Saley-As` (D50) works only with `mock`.
- Roles from `users.role`. A session lasts `SESSION_HOURS`, re-checked against the allowlist on every request. Sign-out deletes the row.
- 10 a minute per IP on `/auth/*`. The same-origin rule stays for POST.
- Pages: `/signin`, `/auth/callback`, `/auth/signout`, a refusal page ("This account may not use Saley").

### Weekly pack and Scorecard deltas (`intel/pack.py`, D117, D118)
- Job `weekly_pack`, cron Mon 14:00 IST, worker only, idempotent on week_start, misfire grace, plain code (no LLM).
- Body: team numbers with "last week N"; Scorecard per industry with deltas, the same rows as `/api/scorecard` (R4-P01); up to 5 late items that block goals; reminders the politeness budget moved to the pack (`reminders.py` `packed`); the next 10 tasks per person.
- "last week N" = the snapshot of the day 7 days before (the Monday before, for the pack). A missing snapshot shows "—" and "no snapshot last week", never 0.
- After the build, a `bot_post` row (shape `pack_summary`, at most 12 lines + a link) waits; it goes out only when `BOT_SHAPES_DRAFT=true`.
- `GET /api/pack?week=YYYY-MM-DD` (a Monday; default latest). `GET /api/scorecard` gains `last_week` fields. Words in words.py and words.js: "last week 91", never "W41".

### Bot (`bot/{deliver,caps,answer,instruct,identity}.py`, D119–D125)
- Identity: `DISCORD_USER_MAP=short:id;...` fills `users.discord_id` at start. An unknown author gets one polite line and no data.
- Delivery: worker job `bot_plan` (every 5 min) moves `queued` to `ready` under the caps. The bot process sends `ready` rows every 15 s through the REST client (egress): one code path for test and live. Channel = test when TEST_MODE=true, else sales; `[TEST]` only in test mode. With SALEY_ENV=dev, any channel other than `DISCORD_TEST_CHANNEL_ID` is refused and logged. The gateway still refuses TEST_MODE=false.
- Caps (pure `caps.plan(posts, now, sent_today)`): at most `BOT_POSTS_PER_DAY` (3) per channel a day, the rest move to the next day ranked; at least `BOT_POST_GAP_MINUTES` (120) apart, a meeting in under 24 h skips the gap; Saturday and Sunday only meetings and reconnects; `USER_HOURS` (default `sid:10:00-19:00`): outside the window a post waits for the next start; answers to questions are never capped.
- Answers: fixed grammar (docs/09 §grammar), plain code, no LLM. Lookups: people at a company, news since a day, what a person works on, P1 without email, due this week. SQL builds the rows; a template writes the answer. Each line has a citation (`[row 412]`, `[fact 881]`, `[story 2201]`). 5 items; `more` shows the next 5. Footer always: `Window: … · N shown · M more · K left out as seen by you.` Seen is marked per person (`saley_mark_seen`). `intel/guard.py` checks the text against the row values. Unknown text: "I do not have that. I can search the web, or ask <person>. Which?" The bot never picks the person; the owner comes from the owner rule only.
- Dashboard Ask card (Today): `POST /api/ask`, the same engine, questions only; it changes only `user_seen` and `bot_exchange`. Add it to the gate step 9 allowed POSTs (as D97).
- Instructions: `DISCORD_INSTRUCT_IDS` = remind me, cancel reminder, note (a note becomes a fact with its author). `DISCORD_APPROVER_IDS` = approve <id>, reject <id> because <reason>: the same SQL functions as the dashboard (`saley_act` / confirm) with surface `discord`, a write at once with a signature and the `UNDO_MINUTES` undo. `instruction_key` (D48) makes chat + dashboard one write. Anyone else: "Sorry, only <approvers> can approve. I did not change anything." The LLM never chooses a person or a stage.
- Shapes: `BOT_SHAPES_DRAFT=false` (default) keeps D27 (only ping and the release ping). True: pack summary, answer, reminder due, commitment nudge, blocker note post only to the test channel. docs/09 gets one example per shape, marked DRAFT.
- CLI: `saley discord roundtrip --test --case pack|answer` posts, reads back, deletes, exits 0 or 1.

### Email (`core/mailer.py`, D124)
`send(draft)`: with `EMAIL_SEND_ENABLED=false` it writes one `.eml` to `EMAIL_SINK_PATH`. `SmtpSender` is built only when the flag is true; `SMTP_HOST` must pass the egress allowlist. The test patches `smtplib.SMTP` and asserts zero calls.

### Gate
The gate's web on `GATE_PORT` runs with `AUTH_PROVIDER=mock` and `BOT_SHAPES_DRAFT=false`. Browser QA signs in through `/signin` (check `sign_in_page`), then runs `weekly_pack_page` and `saley_card`. Only the two roundtrip rows set the draft flag, in the test channel.

## 8. Risks
Removing the loopback bypass breaks many tests (one conftest `signed_in` fixture; a no-session abuse case per route) · a mock provider reachable on a server (dev + loopback only, 404 when Google is configured, R4-A03) · OAuth mistakes (state + PKCE, aud/iss, rate limits) · cron double fire or misfire (unique week_start, mocked clock) · the first week has no snapshot ("—", never 0) · cap logic around midnight and weekends (pure function, IST clock, table tests) · a post reaching a live channel (TEST_MODE, the D125 guard, the draft flag) · bot and dashboard racing on one instruction (`instruction_key`, D48) · answers inventing values (validator, no LLM) · `app.py` growth (routers `web/auth.py`, `web/pack.py`) · Discord rate limits in the roundtrip (one post per case, then delete) · low RAM in browser QA (D112) · abuse-suite drift (never edit a row to pass).
