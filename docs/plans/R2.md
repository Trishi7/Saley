## 3. Design

### 3.1 Migration 0006 (`migrations/versions/0006_writes.py`)
Tables (names as in docs/01 §12.2 and §12.4):
- `decision`: id, kind (column_write, task_done, dismiss, strategy_decision, undo), choice, reason, user_id FK, at, surface (dashboard, chat, card), proposal_id, tab, row_key, role, before, after, instruction_key, state (proposed, confirmed, active), undo_until, undone_at, undone_by, undo_of.
- `sync_outbox`: id, decision_id FK, op (write, restore), tab, row_key, role, value, state (pending, done, failed, held, cancelled), tries, error, next_at. `sync_audit`: outbox_id, before, after, at, by.
- `proposal`: id, type, card_key UNIQUE, entity_type, entity_id, payload, evidence, rank, due_at, state (open, acted, dismissed, expired), shown_at.
- `fact` (docs/03 §3); `commitment` (owner FK, text, due, source_type, source_ref, state, reminders_sent, last_reminded_on, in_pack); `reminder` (for_user, text, fire_at, entity_id, commitment_id, kind before / due_day, state); `ask`; `user_seen` (created now, used in R3).
- Partial unique index `uq_decision_active_instruction` on `decision(instruction_key)` where `undone_at is null and kind in ('column_write','task_done')`. `ix_outbox_pending (state, next_at)`.
- Views for `saley_ro`: `v_decision`, `v_inbox`, `v_commitment`, `v_fact_working_on` (newest, not expired), `v_pending_write` (open outbox overlay), `v_task_inputs`.
- Functions, `SECURITY DEFINER`, `set search_path = public, pg_temp`, owner `saley`, `revoke execute from public`, `grant execute to saley_ro`: `saley_act(user_short, surface, action, targets jsonb, payload jsonb, instruction_key) → jsonb`, `saley_undo(user_short, write_id)`, `saley_confirm(user_short, decision_id)`, `saley_dismiss(user_short, proposal_id)`. Each checks the user's role, takes `pg_advisory_xact_lock(hashtext(tab||row_key||role))` and writes only its own rows. `saley_ro` keeps zero table grants.

### 3.2 Write path (proposed D45)
1. Web checks the lock (`columns.assert_writable` on the cached resolution). Refusal → 403 + `write_refused` log.
2. Web calls `saley_act` in its own short transaction (`act_db` dependency, not the read-only `db`).
3. `saley_act` inserts `decision` (signature, `undo_until = now() + UNDO_MINUTES`) and `sync_outbox` in one transaction; returns `{write_id, undo_until, label}`. That commit is the write (D24, "writes at once"). The UI reads `v_pending_write` and shows the new value at once.
4. Worker job `sheet_push` (every `SHEET_PUSH_SECONDS`, default 2, lock `sheet_write`) drains the outbox: re-resolves headers, `assert_writable` again, reads the cell and stores `before`, writes, appends the Name note, reads back.
5. `SHEET_WRITE_ENABLED=false` → outbox rows stay `held`; Sources and health shows "sheet writes off: Q-R2-1".
6. `sheet_sync` skips a cell with an open outbox row, so a sync never reverts a pending write.
Credential: `saley.sales.writer` defines a `SheetPort` protocol; `GspreadSheet` (scope `spreadsheets`) is built only when `SALEY_PROCESS == "worker"`; `FakeSheet` for tests and dev. `saley dev` runs the worker as a child process (proposed D46). The web never imports the writer. R2-G01 checks the `saley.web.*` import graph, the web settings, the compose `web` service (no key file mount) and that the writer raises in the web process.
Name note (proposed D47): one line per write, `Saley · First Contact Date = 19 Oct 2026 · Sid · dashboard · Sun 19 Oct 14:05 IST · d123`; undo: `Saley · undone d123 · Kushal · dashboard · 14:09 IST`. Last 10 lines kept; human text above is kept.

### 3.3 Undo
`saley_undo` refuses past `undo_until`, a write already undone, or a non-approver ("Undo window closed at HH:MM"). A pending or held outbox row is cancelled with no sheet call. Otherwise op `restore` with `before`; the worker restores only if the cell still holds `after`, else fails with "cell changed since, not restored" and logs it.

### 3.4 Idempotency and the 2 s rule (proposed D48)
`instruction_key = sha256(action | sorted targets | role | normalised value)`: no user, no surface, so chat + dashboard = one key. The same key again returns the first decision with `already: true` and no new write. A different user on the same row and role within `ACT_COOLDOWN_SECONDS` (2) gets 409 "Already done by Sid at 14:05" (words.py).

### 3.5 My tasks (`saley/intel/tasks.py`, pure functions; owner per D31)
- Sid: LI connections to confirm (LI added, no connected date; Done writes LI Connected Date = today); R05 first LinkedIn picks (top 5 P1 then A–F, First Contact blank; Done writes First Contact TRUE, Type LI, Date today); R14 reconnects due (D14, D36; Done = `task_done`, Reconnect Date is read-only); meetings today (Done writes Meeting Status "completed").
- Vaishnavi: R06 research (connected, no email, > 3 days; Done = `task_done`, or `email_write` when EMAIL_WRITE_ALLOWED); R13 email steps (anchors per proposed D51).
- Kushal: decisions to confirm, Inbox cards, others' writes inside their undo window.
- Everyone: commitments due today.
- A Done on a STEP-block task never writes the sheet (R13, docs/10); it logs `task_done` and a `touch(source='dashboard')` (proposed D49).

### 3.6 Inbox lifecycle
Rules create proposals with a stable `card_key` (for example `meeting_status:<row_key>:<meeting_date>`); `UNIQUE(card_key)` means the same idea is never inserted twice, in any state. open → shown → acted or dismissed (`saley_dismiss` + `decision(kind=dismiss)`). R2 sources: meeting date passed with status booked ("Mark completed?"), LI likely connected, D36–D38 waiting for a confirm. The Inbox also lists open asks, reminders and strategy decisions, never a write the human already asked for.

### 3.7 Commitments and politeness
- Meeting notes: `.md` / `.txt` in `MEETING_NOTES_DIR`; plain-code patterns ("I will / I'll / will send … by <day>"), owner from the speaker line, no LLM (proposed D52). Due date only from the note text; none → empty, never guessed.
- Mail: `saley/intel/mail.py`, IMAP read-only; `MAIL_USER` empty → health "mail: not configured", job skipped (Q-R2-3).
- Reminder budget (`reminders.py`): at most one before the due day and one on the due day, then `in_pack = true`, no more. All text from words.py; a test greps for "overdue". R4 adds Discord delivery with caps and weekend silence.

### 3.8 Decisions view
`GET /api/decisions?person=&surface=&undo=open|undone|closed&state=` from `v_decision`. `saley decisions import` reads the docs/DECISIONS.md table (human rows → active, "proposed" rows → proposed). Confirm sets confirmed_by, at, surface, state active (S45).

### 3.9 Drawer working_on
Job `facts_refresh` after `sheet_sync` writes `fact(kind=working_on)` from About PoC and Research Paper Link, and from meeting-note facts, with `source_type`, `source_ref`, `observed_at`, expiry 90 days. The drawer shows text, source and date, else "None on file".

### 3.10 UI (`static/app.js`, `app.css`)
Done tick per task; toast "Saved · Undo (9:59)" with a countdown; new views Inbox, Commitments, Decisions; pending writes show "sheet updates in a few seconds". Every POST sends `X-Saley-Act: 1` and passes the same-origin check; the server refuses a POST without it. Dev only: a "View as" select sets `X-Saley-As: <short>`, loopback only (proposed D50).

### 3.11 browser_qa
Step 9: the allowed non-GETs are exactly `POST /api/act`, `/api/undo/*`, `/api/decision/*/confirm` (and the dismiss path); any other method or path fails. Every `[data-act]` control sends exactly one allowed POST and changes the page. Named checks: `done_undo` (tick Done → toast → Undo → old value back) and `confirm_dismiss` (confirm a seeded proposed decision; dismiss a card, reload, card gone). Seed and teardown: `scripts/qa_seed.py` (dev database + FakeSheet), teardown always.

## 7. Risks
- SECURITY DEFINER function bug widens web rights → fixed action whitelist, pinned search_path, execute revoked from PUBLIC, security review.
- The migration may not be able to set the function owner (needs `saley_admin` in `saley`) → `roles.sql` repeats the step as superuser (pattern of 0005).
- Sync races a pending write → skip pending cells; parity row R2-S01.
- A human edits a cell inside the undo window → restore only when the cell equals `after`; else refuse and log.
- Columns move between web check and push → the worker re-resolves and re-checks every push.
- Google write quota 60/min/user → batch per row, backoff, `failed` state on health.
- The 2 s rule can be flaky → tests use the clock fixture, never sleeps.
- browser_qa needs a seeded dev DB → seed and teardown always run.
