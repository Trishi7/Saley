## 3. Design

### Tables
- `0010_news_signals.py`: `news_sources` (registry per docs/05 §6), `news_editions`, `news_source_runs` (dropped_seen, dropped_gate, dropped_copy), `news_seen`, `news_dropped`, `news_stories` (fingerprint, outlets[], outlet_count, kind news|paper, importance, impact, tag, why, scored_at, scorer_backend), `news_sent` (empty until R4), `signal` (docs/03 §3.3 + confidence, verify), `search_hit` (query, engine, url, title, account_id, found_at), `search_request`. Views for saley_ro only: `v_signal_all`, `v_signal_linked`, `v_event_targets`, `v_suggest_{warm,best,newco,res}`, `v_news_funnel_day`, `v_news_source_health`, `v_needs_look`, `v_saley_suggests`, `v_user_seen`.
- `0011_row_add_seen.py`: `decision.kind` allows `row_add`; `sync_outbox.op` allows `append`; functions `saley_mark_seen(user, item_type, ids[], query_id)` and `saley_request_search(user, account_id)`; `saley_act` gets a `row_add` branch. Downgrade runs as the function owner (H4 pattern).

### Sources and schedule (D70, D71)
- News jobs run only in the `saley news` process. `saley dev` and the gate never fetch (one bounded live fetch is the separate row R3-N03).
- Editions 06:30, 12:00, 17:00, 22:00 IST; arXiv 10:00; OpenAlex 07:30; cleanup 03:00.
- Registry `src/saley/news/registry.yaml`, seeded by `saley news seed`.
- Google News lanes: `news.google.com/rss/search?q=…&hl=en-IN&gl=IN&ceid=IN:en` (+ GB, US for broad): names (15 per query, rebuilt from the sheet), broad, topics, voice, hires, competitors.
- arXiv `https://export.arxiv.org/api/query`, categories per docs/05 §3.6, keyword filter before store.
- OpenAlex `api.openalex.org/works` per Academia PoC; a person counts as found only on name + affiliation.
- Hosts are on the allowlist already. Only title, summary and link are stored. Google article links are stored, never fetched.
- Conditional GET, 50 items per fetch, docs/05 User-Agent, back-off 60 s → 1 h → 4 h → 24 h.

### Clean and dedupe (`news/clean.py`, docs/04 §2)
Canonical URL hash in `news_seen` → skip. Fingerprint = first 12 real title words, sorted, hashed; a match within 36 h adds an outlet. Gate: AI-only sources skip it; general lanes need an AI word, an entity or a flag; a failure goes to `news_dropped`.

### Scoring (D72, `news/scorer.py`)
- Schema `ScoreBatch{items:[{id:int, importance:1-5, impact:0-3, tag:Opportunity|People|Risk|Market|Tender|Discover, why:str≤200}]}`.
- Stories go in DATA blocks via `llm.complete` with `LLM_SMALL`; ≤ `SCORER_BATCH` (40) per batch, ≤ `SCORER_EDITION_CALL_CAP` (6) calls per edition.
- Per-story cache key = model + rubric version + title + summary in `llm_cache` for `LLM_CACHE_DAYS`; only misses go to the model.
- Unknown ids dropped; missing ids carried to the next edition; `why` must pass the validator, else empty.
- Missing key, cap reached or bad output → the deterministic `rules` backend; the row records the backend; a story is never scored twice. `LLMCapReached` pauses text jobs until the next day.

### Validator (`intel/guard.py`)
Extracts URLs, emails, numbers, dates and capitalised name runs; any value not in the input facts is a violation and the text is refused. Used by scorer `why`, `action_hint` and the `row_add` payload.

### Linking (D74, `news/signals.py`)
Only scored stories. Two matches (name + company, name + domain, author + affiliation) → confidence 3; one → confidence 1 + "verify". Account names under 5 characters or common words need the alias table or a case-exact match. `action_hint` (`LLM_SMALL`) only for importance ≥ 3, ≤ `ACTION_HINT_DAILY_CAP` (40) a day, validated; else "no hint yet" (D79).

### Endpoints (new router `web/signals.py`)
`GET /api/signals?tab=all|linked&range=day|week|month|year&cat=&src=&tag=&entity=&limit=&offset=&include_seen=` (rank: ours, impact, importance, outlets, newest); `GET /api/events?when=upcoming|past`; `GET /api/suggest/{warm|best|newco|res}`; `GET /api/news/funnel?day=`; `POST /api/seen`; `POST /api/act` actions `row_add` and `find_people`. Every list returns `window{from,to,label}`, `left_out_seen`, `last_computed`.

### Seen (D75)
The page posts the ids it showed (idempotent). Seen is per person. Lists show unseen first, then "N you saw are left out · Show them". Conflicts with docs/08 Shared rules ("does not apply to the dashboard") → Q-R3-6.

### Suggestions, search and row_add (D76, D77)
- "Find people" on newco is the human's yes (R11) → `search_request`; worker job `search_requests` runs it.
- SearXNG JSON if `SEARXNG_URL` is set, else `https://html.duckduckgo.com/html/?q=site:linkedin.com/in "<company>" <role words>`. DuckDuckGo `uddg` links are decoded locally, never followed. ≤ 1 call per `SEARCH_MIN_GAP_SECONDS` (5, D82), ≤ `SEARCH_DAILY_CAP` (50) a day. Only result URL + title stored.
- Add form filled from sheet values and the hit; the human edits name and designation, then Add → `saley_act(row_add)` → decision + outbox `append`.
- Worker: re-resolve headers; check new-row roles (docs/10); LI Url only for a `linkedin.com/in/` URL; refuse a duplicate name + company; append with Sr No = max + 1; Name note `Saley · row added · <user> · <surface> · <time> · d<id>`; read back.
- Undo inside `UNDO_MINUTES` deletes the row only when every Saley cell is unchanged. `SheetPort` gets `append_row`, `delete_row`. The next sync shows the person.
- `saley sheet roundtrip --test-tab --row-add` runs the same in SALEY_TEST, then deletes the tab.

### Today, health, Apollo
- Today order: numbers, my tasks, needs a look, blocked, Saley suggests. Needs a look: linked signals importance ≥ 4, events ≤ 3 days, "replies: mail not configured" (Q-R2-3). Saley suggests: top 3 newco + warm, one button each.
- `/api/health/full` `news` block: tried, answered, fetched, dropped seen/copy/gate, deduped, scored, scored ≥ 4, linked, sent ("—, no digest until R4"), each with an `href`; failed sources; per-source counts; `search` block; `apollo` block "off" (D78: needs flag + cap > 0 + pipeline).

## 5. Proposed decisions
- D70 news jobs only in `saley news`; gate and `saley dev` never fetch.
- D71 R3 sources: Google News, arXiv, OpenAlex only; no article page fetch.
- D72 batch scorer, per-story cache, `rules` fallback, never scored twice.
- D73 funnel terms: fetched = items seen in runs; deduped = unique stories stored; scored; linked = stories with ≥ 1 signal; linking only on scored stories, so the funnel always goes down.
- D74 two-match linking; one match = confidence 1 + verify; short or common names need an alias.
- D75 per-user seen on dashboard lists via `POST /api/seen` (conflicts with docs/08 Shared rules; Q-R3-6).
- D76 `row_add` values only from sheet rows, search hits and the human's edits; duplicates refused; undo deletes only an unchanged row.
- D77 profile search only on a human "Find people" click (R11); SearXNG then DuckDuckGo; URLs stored, never fetched.
- D78 Apollo needs flag + cap > 0 + pipeline; off in R3.
- D79 `action_hint` only for importance ≥ 3, ≤ 40 a day, validated; else "no hint yet".
- D80 LLM defaults move to the current models: `LLM_SMALL=claude-haiku-5-5`, `LLM_MID=claude-sonnet-5-5` (the R1 defaults are an older generation).

## 7. Risks
Old model ids (a live 404 fails R3-L02; the error names the model) · DuckDuckGo blocks or HTML changes (fixtures, 5 s gap (D82), cap 50, "unavailable") · Google News 429 (per-host bucket, wait for the next edition) · false links on short or common names (D74, verify flag) · prompt injection in headlines (DATA blocks, fixed schema, validator, the LLM never decides) · LLM non-determinism (per-story cache, fixtures, pure-code `rules`) · humans editing the sheet during a row add (re-read, duplicate check, Sr No at push time) · row_add undo deletes a row (only when unchanged, found by key) · 0011 check changes need the function owner (H4 pattern) · `app.py` size (new router) · abuse-suite drift (never edit a test to pass) · cost (~6 scorer calls per edition + 40 hints, far under 400; the release live call is counted in `llm_calls`, job `release_smoke`).
